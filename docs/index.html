Built for agent work that needs evidence

A loop is not a prompt. It is a repeatable operating boundary for long-running coding work: what the agent may change, how progress is reported, and when a human must step in.

The loop is the guardrail

Ariadne, the dream architect, is the metaphor: build the maze first, leave a thread through it, and make every pass observable.

1

Inspect real state

Read files, tests, issues, logs, or remote state before deciding what to change.

2

Act small

Limit each turn to the smallest change that can move the verifier.

3

Verify evidence

Use concrete gates instead of vague confidence: tests, screenshots, readbacks, diffs.

4

Decide the next turn

Stop when done, continue when bounded, roll back on damage, ask a human before external effects.

Start with a snapshot, not a meeting.

Use the Builder to capture goal, current state, progress, constraints, verifiers, and external effects. Ariadne Loop turns that snapshot into a packet your coding agent can follow.
