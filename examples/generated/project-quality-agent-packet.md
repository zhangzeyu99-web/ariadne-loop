# Ariadne Loop project quality Loop Agent Packet

## Goal
Improve Ariadne Loop into a high-quality public project without broad churn, stale outputs, or unverifiable claims

## Current State
The project has a Python CLI, loop builder core, GitHub Pages docs, bilingual homepage and builder pages, generated examples, schemas, and pytest coverage. Recent homepage and builder copy changes are live on GitHub Pages. Each new optimization turn must start from the current repository state, not memory.

## Constraints
- Read current files, tests, docs, CLI behavior, and git state before changing anything
- Prefer small reviewable improvements over broad rewrites
- Do not change public CLI commands, JSON schema, package metadata, or published URLs without tests and docs
- Keep generated examples in sync with the current CLI output
- Preserve bilingual public pages; run the CJK output quality gate when touching Chinese HTML or docs
- Do not invent quality claims without evidence from tests, browser checks, file readback, or remote readback
- Do not tag, release, publish packages, or make external-impact changes without human confirmation

## Cycle
- `inspect`: Read real context, existing artifacts, and previous state. Confirm this turn has one verifiable target. -> Turn scope, known evidence, gaps, and explicit non-goals
- `act`: Take the smallest useful action toward the goal: Improve Ariadne Loop into a high-quality public project without broad churn, stale outputs, or unverifiable claims -> This turn's artifact or change list
- `verify`: Run or perform these verifiers: python -m pytest -q passes; python -m loops_assistant check --input examples/generated/project-quality-loop.json passes; Generated examples that were touched are regenerated by the current CLI and validate; If public HTML changes, desktop and mobile browser checks show no text overflow, clipped controls, or broken language switching; If Chinese public content changes, output_quality_gate.py passes with --expect-cjk; README, docs, and Pages links point to existing files or live URLs; git diff contains only changes needed for the selected quality improvement -> Pass, fail, or missing-evidence status for each verifier
- `decide`: Decide whether to continue, stop, rollback, or ask for human confirmation based on verifier results. -> Next action and stop decision

## Verifiers
- `gate-1` (command): python -m pytest -q passes
- `gate-2` (checklist): python -m loops_assistant check --input examples/generated/project-quality-loop.json passes
- `gate-3` (checklist): Generated examples that were touched are regenerated by the current CLI and validate
- `gate-4` (checklist): If public HTML changes, desktop and mobile browser checks show no text overflow, clipped controls, or broken language switching
- `gate-5` (checklist): If Chinese public content changes, output_quality_gate.py passes with --expect-cjk
- `gate-6` (checklist): README, docs, and Pages links point to existing files or live URLs
- `gate-7` (checklist): git diff contains only changes needed for the selected quality improvement

## Stop Rules
- Stop when every verifier has current evidence and passes.
- Stop and narrow the problem after the same verifier fails twice.
- Stop and ask for confirmation when the goal, input, or permissions do not match the current context.
- Ask for confirmation before external-impact actions: commit, push, GitHub Pages update, GitHub release, package publish

## Rollback
Revert this turn's output or keep the prior state, record the failing evidence, then return to inspect with a narrower scope.

## Human Gates
- Ask for human confirmation before changing external state, publishing, sending, deleting, or paying.
- Risk is medium; do not expand scope after failure.
- After an external-impact action, read back the real target before reporting success.

## Budget
- max_iterations: 3
- max_minutes: 60

## Report Contract
Return JSON only. Do not add prose outside the JSON.

```json
{
  "action_id": "inspect|act|verify|decide",
  "status": "continue|stop|needs_human|rollback",
  "evidence": ["specific evidence observed in this turn"],
  "next_step": "the next concrete action",
  "passed_verifiers": ["gate ids that passed in this turn"],
  "failed_verifiers": ["gate ids that failed in this turn"]
}
```
